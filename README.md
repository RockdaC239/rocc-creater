# Rocc 创作工作台

面向抖音、小红书、X 的个人内容工作区。

公开仓库只保存工作台说明、工作约定、SOP 和可复用工具；本地素材、作品文稿、灵感记录、历史归档与凭据默认不提交。音视频和常见工程、压缩文件也已按扩展名忽略；Git 不会自动按文件大小忽略未知格式，新增其他大文件时需补充规则。

新电脑克隆后，在仓库根目录执行 `mkdir -p 收件箱 内容项目 灵感选题 工作流 历史归档` 即可恢复空目录；本地素材需单独迁移。

## 从哪里开始

| 目录 | 用途 |
| --- | --- |
| `收件箱/` | 新视频、录音、截图、链接等待整理输入；暂时不知道放哪里就放这里 |
| `内容项目/` | 一期内容一个目录，集中保存素材、剪辑产物、文稿和发布材料 |
| `灵感选题/` | 收集全网灵感、来源链接和候选选题 |
| `工作流/` | 后续整理剪辑、材料准备、Notion 入库、分发的 SOP |
| `历史归档/` | 整理前已有的旧作品、音频、转写、清单和脚本 |
| `.agents/skills/` | 已有的工作区 Skill；继续保留供后续调用 |

上传一期素材时，可以直接放入 `收件箱/`，然后告诉助手“把这批素材整理成一期内容”。整理到 `内容项目/YYYY-MM-DD_主题/` 后，按需要创建 `素材/`、`剪辑/`、`文稿/`、`发布/`，不用提前建立空目录。

## 预期工作链路

素材上传 → AI 剪辑 Skill / SOP → 成片与作品材料 → 作品文字版入 Notion → 抖音、小红书、X 分发。

独立的选题链路：全网搜集 → 保留来源和采集日期 → 提炼选题 → 进入一期内容项目。

已完成本地整理和工作约定，并验证 Notion 连接可以读取、创建作品子页面和移入回收站。自动剪辑、联网采集、自动入库流程和跨平台发布仍待后续依据实际 Skill 和 SOP 落地。

## 一期内容的材料约定

- 素材：保留上传的原始文件；衍生产物另存。
- 剪辑：剪辑工程、中间文件、字幕和最终成片。
- 文稿：转写文本、校对稿、适合入库的作品文字版。
- 发布：按抖音、小红书、X 分别准备标题、正文、封面和适用的话题；记录实际发布链接与时间。
- 项目说明：需要时在项目内建立 `README.md`，记录当前进度、下一步、Notion 页面链接及各平台发布状态；生成材料不等于已入库或已发布。

## 灵感记录约定

先用普通 Markdown 记录，不预建数据库。每条尽量包含：选题、原始链接、作者或平台、采集日期、可切入角度。来源中的观点与自己的判断分开；是否使用素材及如何引用，在具体创作时处理。

## 历史资料

整理前的文件整体迁入 `历史归档/2026-09-旧作品整理/`，内部相对位置和文件名保持原样。`历史归档/整理记录.json` 记录搬迁核对信息。

旧转写脚本使用当前目录下的音频、输出目录及密钥文件。要沿用旧默认路径，先从工作区根目录进入归档：

```sh
cd 历史归档/2026-09-旧作品整理
python3 asr_batch.py --help
```

实际转写依赖本机已安装 `dashscope` 和有效凭据，并会调用外部服务。原有 `--srt` 会跳过已有 `.txt` 的条目，补字幕时不要直接删除已有转写，可用新的输出目录。

密钥仍保留在原资料包内，权限保持不变。`.gitignore` 已排除凭据、本地内容、历史资料和临时产物；忽略规则只防止未来误提交，不提供加密或备份。
