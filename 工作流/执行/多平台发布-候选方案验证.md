## 不能直接采用原版的原因

1. 两平台调用 `utils/base_social_media.py:set_init_script` 注入 `stealth.min.js`；抖音还传 `--disable-blink-features=AutomationControlled`。依赖 Patchright 本身定位为反检测 Playwright。只删除注入脚本并不足够，需要换回标准 Playwright 并去掉隐藏自动化特征的配置，再重新验收。
2. 两个平台的视频流程都在 `while True` 中点击发布，等待成功 URL 仅 3 秒；异常后继续循环。提交结果未知时可能再次点击，外层简单重跑 CLI 无法保证不重复。
3. 成功 URL 只证明页面进入成功路径，不能证明审核通过或定时已实际发布。CLI 返回账号文件路径/退出码，没有可直接满足需求的上传、发布、审核分别回执。
4. CLI 新版小红书路由是 `uploader/xiaohongshu_uploader/main.py`，主要通过官方创作者网页操作；另有旧 `uploader/xhs_uploader/main.py` 调用本地签名服务。必须禁用旧流程，不接入该签名服务。本轮对目标调用链的源码检查未发现主动调用私有发布 API；这不是全仓库或真实网络流量审计结论。
5. 会话可在该工具自身登录后复用；不等于自动共享当前 Ego/Chrome 已登录标签。现有会话迁移尚未验证，不能承诺首次免扫码。失效、验证码和短信应暂停交给本人处理，不自动绕过。

来源：[抖音实现](https://github.com/dreammis/social-auto-upload/blob/3847fff01f5434a8a32829833163cd6723cabc59/uploader/douyin_uploader/main.py)、[小红书浏览器实现](https://github.com/dreammis/social-auto-upload/blob/3847fff01f5434a8a32829833163cd6723cabc59/uploader/xiaohongshu_uploader/main.py)、[共同注入](https://github.com/dreammis/social-auto-upload/blob/3847fff01f5434a8a32829833163cd6723cabc59/utils/base_social_media.py)、[Patchright 定位](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright)。

## 最小接入方案（尚未实施）

只接入现有流程第 5 环节。复用上游 `sau` 命令与 Skill 的字段约定、文件选择、封面、文案和定时操作；不复制平台选择器与浏览器操作代码。

必须的上游有限补丁：目标调用链换标准 Playwright、移除 stealth/反检测参数；增加填完材料后的暂停及单次提交接口；去掉发布循环重击；输出结构化上传/提交结果。验证与短信交给用户。补丁固定 commit，升级需复验。

工作区只增加三个职责：

- 一份发布执行文档：指向固定版本、登录与失败处理，并由内容生产第 5 环节引用。现有剪辑、封面、Notion 不改造。
- 一个统一 CLI 入口：拟为 `python3 工具/内容发布.py prepare|submit|status <本期项目>`，只做参数校验、调用上游、确认绑定和状态落盘，不重写网页操作。Skill 负责向用户展示两平台材料并取得确认。
- 每期 `发布/发布任务.json` 与状态文件：公用视频、封面可复用；抖音/小红书各自记录账号、标题、正文、话题、时间、可见范围与结果。登录文件存 Git 外私有目录，权限收紧，不进项目日志、仓库或 Notion。

发布路径：校验材料 → 复用会话 → 上传并填表 → 展示两平台最终材料、账号、封面与时间 → 用户明确确认 → 单次提交 → 核对官方成功页面和内容管理列表 → 分别记录审核/定时/可见状态。

确认绑定材料文件 SHA256、平台、账号、完整文案、话题、时间及可见范围；任一项变化必须重新确认。CLI 本身不能把一个通用 `--yes` 或历史标题确认当作本次发布授权。

状态至少分开保存 `upload`、`submission`、`review`、`publication`，附时间、证据和作品 ID/链接（页面实际提供时才填）。进入成功页面只记“提交成功、审核待核实”；定时受理只记“定时已受理”。正式完成需官方证据确认审核通过且到时实际发布；拒审、处理中、结果未知都不能标已完成。

防重：以项目+平台+账号建立持久任务并加进程锁，另保存材料指纹。点击前先持久化“提交中”，崩溃恢复转“结果未知”，禁止自动重发；先查官方内容列表。已经提交/定时/发布的任务拒绝重复提交，改文案也不能绕过原任务。只有能确认尚未提交的上传失败可有限重试；有草稿则优先恢复。网页自动化无法承诺严格 exactly-once，靠未知状态停机和人工核对避免盲重试。

原版没有独立审核查询 CLI。最小第一版可以通过既有浏览器工具只读核对官方管理页，并保留人工确认；若要求全自动持续审核同步，需要额外维护页面读取逻辑或获得官方接口授权，不在本次最小方案中伪称已支持。

## 下一阶段验收顺序

先完成有限补丁和离线确认/防重测试，再用标准浏览器验证两平台登录与会话复用、上传指定 10 秒素材、封面/文案/话题/定时填表；停在提交前。只有用户确认最终内容与可见范围后，才各提交一条并核对审核结果；如果仅自己可见是测试前提而页面无法设置，则不发布。会话二次运行、提交超时和进程中断恢复都需验收。
