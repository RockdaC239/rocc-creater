# Agent 口播剪辑：原片、工程、预览、一次导出

上级：[内容生产工作流](../内容生产.md)。Agent 执行本流程，不要求用户操作剪映。借鉴非破坏性编辑：原片只读，JSON 保存编辑决定，本地引擎合成预览和成片。当前支持 9:16 单人口播，交付 1080×1920、30 fps。

## 分工与状态

- Agent：理解转写、选择入出点、校对字幕、编辑 JSON、运行工具、检查预览和核验结果。
- 本地工具：识别、时间映射、字幕渲染、编码、抽帧与技术检查；不让大模型逐帧操作字幕或重复识别。
- 用户：看成片效果、提出修改；未要求发布时，不做发布。

项目沿用 `内容项目/YYYY-MM-DD_主题/`。每次修改使用新的工程子目录和输出版本名，原片、旧工程、旧产物保留。README 分别记录工程建立、工具运行、技术核验、听审及用户确认，不能互相替代。

## Agent 执行顺序

1. **迁移并登记原片**：枚举收件箱真实文件（媒体被 Git 忽略，不能只用 `rg --files`），按上级工作流的迁移规则，将本次输入移动至对应项目 `素材/`，核验完整后再开始剪辑；收件箱不保留副本。用 ffprobe 读取显示方向、时长、音轨、帧率、色彩和位深，保存迁移前后路径与 SHA256。迁移后的素材只读，工程只引用项目内路径，禁止改写原件。当前渲染目标固定为 1080×1920/30 fps；其他画幅或帧率须先明确方案，不隐式降格。
2. **识别并缓存**：只提取音频，保存原始 WAV、TXT、SRT、带时间戳 JSON；后续改字幕和剪辑复用识别结果。原始转写保留，校对另存。疑似错字只复核相关短音频。
3. **编写工程**：JSON 的 clips 始终引用原片，填写源入点、出点；captions 保存源时间及校对文字。保留语义停顿和完整论证，只删明确的口误、**口糊（含糊、说不清、半截含糊重说）**、重录、重复或无效等待。字幕按短句和语义分段，不按全文长度平均分配时间。入出点还必须遵守下方「节奏与接缝硬性规则」。
4. **编译工程**：运行渲染器 `--prepare`，得到素材信息、成片时间字幕、滤镜图和命令；这个阶段不编码视频。参数错误、缺音轨、字幕重叠、出点越界或不支持的色彩格式必须先修复。
5. **生成短预览**：从工程另存一份预览工程，选取开头、每段新素材的首次切入、长字幕和结尾，各保留约 2–4 秒，仍引用同一批原片、使用同一渲染路径。不同目录保存预览产物，不能与整片并行改写同一份 ASS 和日志。核对首帧及下一帧、切口、字幕位置/大小/白色、显示方向和片尾。HDR 用支持 HDR 的原生显示抽帧检查，不能用未经色彩管理的普通 PNG 判断发白。
6. **一次最终导出**：预览核验通过后，从原片统一读取、剪接、加字幕和渐隐，直接编码最终文件。修改后重新从原片渲染，不从上一版 MP4 叠加效果。不要求用户操作其他剪辑软件。
7. **核验与交付**：运行核验器，保存报告和原片/成片对照帧；再目视检查字幕边界、首帧及片尾。保存原件哈希与首次登记值对比。报告未通过就修工程或引擎后重新预览，不把失败文件当交付。返回 MP4、工程和核验报告；完整听审没有执行时明确标注。

## 原片与色彩原则

当前原片为 iPhone HLG/Dolby Vision 兼容层。默认直接保留 HLG，采用 HEVC Main10、10 位、BT.2020/HLG/BT.2020nc，交付 HLG HDR MP4；统一烧录白色字幕并渐隐。普通 BT.709 SDR 原片使用 H.264 SDR。旋转应用后用无损封装清除残留旋转标记，不再编码画面。

- 不再把“整段原片先转 SDR/ProRes”作为默认前置步骤。旧 `HDR转SDR.swift` 路径已发现首帧颜色不一致，仅保留为历史排查工具。
- HDR/SDR 混合、PQ、其他画幅等未经验证的输入应报错，Agent 记录阻塞和下一步，不能默默转换。
- 加字幕和渐隐需要重新编码；本方案减少处理环节，不承诺与原文件逐比特一致。保留 HLG 兼容层，不继承原 Dolby Vision 动态元数据，不宣称保留完整 Dolby Vision。
- 发布平台的 HDR 兼容性另行验证。需要 SDR 版本时单独验证转换流程，不能改标签冒充转换，也不能复用已知首帧异常的中间文件。

## 工程格式与修改方式

路径相对于工程 JSON 所在目录；clips 可重排或删减，字幕仍采用源时间。渲染器负责把字幕重算到新时间线。字幕字号/位置在工程中修改，不必改工具代码。

```json
{
  "font": "~/.cache/rocc-edit/SourceHanSerifCN-Heavy.otf",
  "output": "../../发布/口播_v1_HDR.mp4",
  "subtitle": {"font_size": 72, "scale_y": 96, "x": 540, "y": 1494},
  "clips": [{"source": "../../素材/IMG_2604.MOV", "start": 0, "end": 10.1}],
  "captions": [{"source": "../../素材/IMG_2604.MOV", "start": 1.85, "end": 2.96, "text": "开店赚钱"}]
}
```

例子的相对路径只适用于工程位于 `剪辑/某版/` 时；Agent 必须按实际目录计算，不能直接复制无效路径。

## 已确认的默认口播配置（2026-10-30）

用户已确认 `字幕Heavy黑色阴影_最后10秒_HDR.mp4` 的效果。以后口播默认使用以下配置，不再以旧 Bold 模板为准：

| 项目 | 默认值（1080×1920） |
| --- | --- |
| 字体 | 思源宋体 Heavy，文件 `SourceHanSerifCN-Heavy.otf`，ASS 明确指定 `SourceHanSerifCN-Heavy` |
| 字号与比例 | ASS 字号 72，ScaleX 100%、ScaleY 96% |
| 位置 | 水平居中，锚点 (540,1494) |
| 文字 | 白色、无描边 |
| 阴影颜色 | 黑色 #000000 |
| 阴影透明度 | 约 55%，即不透明度约 45%（ASS alpha 8C） |
| 阴影距离 | 约 10px，偏移 (+7.1,+7.1) |
| 阴影模糊 | ASS blur 9 |
| 结尾 | 整体渐隐 0.5 秒，音频末尾 0.12 秒防突断 |

阴影随 Heavy 字形同步变粗。上述参数是用户看样片确认的最终值，不再把它们描述为待确认的旧剪映滑块换算。其他分辨率应保持视觉比例并单独预览，不机械照搬像素值。首次运行下载 Adobe 官方思源宋体 CN Heavy 到 `~/.cache/rocc-edit/SourceHanSerifCN-Heavy.otf`；可用镜像 `https://mirrors.tuna.tsinghua.edu.cn/adobe-fonts/source-han-serif/SubsetOTF/CN/SourceHanSerifCN-Heavy.otf`。渲染器检查字重，日志必须确认真正加载 Heavy，不允许回落到 Bold。旧工程显式指定 Bold 时需要更新其 font 路径。

## 默认讲话响度

用户指定参考：`历史归档/2026-09-旧作品整理/作品原视频/copy_9C294077-9BF1-40EB-92DA-0CA1F9B9074D.MOV`（465.13 秒）。本地 FFmpeg loudnorm 测得整条音轨：综合响度 **−11.58 LUFS**、真峰值 **+1.09 dBTP**、响度范围 **3.50 LU**。这不是分离后的纯人声测量，可能包含背景声。

未来口播以 **−11.6 LUFS** 综合响度为目标，真峰值目标上限 **−1 dBTP**；参考片超过 0 的真峰值不照搬。当前只完成参考测量和目标记录，**渲染器尚未启用自动响度归一化，仍保留源音量**。十秒样片的初次自动归一化尝试未通过复测，不纳入默认工具；不得宣称默认导出的响度已经统一。以后需要执行此目标时，Agent 应先完成独立的音频处理验证并复测成片，再更新实现状态。

## 工具调用

工作区根目录执行，工程路径替换为本期实际路径：

```sh
# 首次识别；文件名不能与原件重名，已有识别结果直接复用
ffmpeg -n -i 原片.MOV -vn -ar 16000 -ac 1 -c:a pcm_s16le 原始音频.wav
whisper-cli -m ~/.cache/rocc-edit/ggml-base-tuna.bin -l zh -f 原始音频.wav -ojf -otxt -osrt -ml 24 -of 原始转写

# 先检查工程，再用预览工程导出，检查通过后运行完整工程
python3 工具/口播渲染.py 本期工程.json --prepare
python3 工具/口播渲染.py 预览工程.json
python3 工具/口播渲染.py 本期工程.json
python3 工具/口播核验.py 本期工程.json
python3 -m unittest discover -s 工具 -p 'test_*.py'
```

[渲染器](../../工具/口播渲染.py)生成 `media.json`、`captions.ass`、`captions.srt`、`render.ffgraph`、`render-command.json`、`render.log`；不覆盖已有 MP4。工程加这些文件共同构成可复现的编辑记录。改版本须用新子目录，避免覆盖旧工程衍生文件。

[核验器](../../工具/口播核验.py)完整解码成片，核对时长、音视频时长差、方向、色彩标签、HDR 位深及字幕时间；通过[原生抽帧](../../工具/原生抽帧.swift)对比首帧及每个切入点的原片/成片颜色，保存独立核验目录。首帧像素平均差阈值 3，其余切点中央区域色彩均值差阈值 12；阈值是报警规则，不是画质分数。抽检不能证明每一帧或声音都正确，复杂画面必须补充目视检查。核验器不替代剪辑内容和听感审查。

依赖：FFmpeg/ffprobe、Python imageio-ffmpeg 和 Pillow；macOS AVFoundation/Swift 用于正确显示 HDR 抽帧（不是转码步骤），本地 whisper.cpp 用于识别。模型和字体缓存于 `~/.cache/rocc-edit/`，首次准备后复用，不需云端调用或凭据。
